# Метеонаблюдения по районам — вариант 14

- **Модель.** Район, станция, наблюдение (record: момент времени, температура, давление, скорость и направление ветра). Перечисление направлений ветра — восемь румбов с диапазоном градусов и методом «румб по азимуту». Перечисление явлений погоды.
- **Базовый уровень.** Минимум, максимум и среднее за период по району; суточный ход температуры; дни с осадками; загрузка наблюдений из массива строк заданного формата с выбросом собственного исключения на некорректной строке — с указанием номера строки.
- **Повышенный уровень.** Станции в разных часовых поясах: приведение наблюдений к общей шкале через Instant и корректное сравнение «в один и тот же момент». Поиск дней, отклоняющихся от средней нормы более чем на заданную величину.
- **Акцент.** Instant и часовые пояса, перечисление с полями, исключения при разборе.

## Модель и структура

- `District` — record с ID и часовым поясом.
- `Station` — record с ID и ссылкой на район. Часовой пояс станции
  определяется через `station.district().zone()`.
- `Observation` — record: ID станции, `Instant`, температура °C, давление гПа,
  скорость м/с, направление ветра и одно явление погоды.
- `WindDirection` — восемь секторов по 45°.
- `WeatherPhenomenon` — NONE, SUNNY, CLOUDY, RAIN, SNOW, HAIL, FOG, THUNDERSTORM.
- `ObservationCalculation<R>` — типизированный интерфейс с полиморфным `calculate`.
  `WeatherMetric` считает min/max/average по выбранному показателю,
  `DailyTemperatureCalculation` строит суточный ряд температуры, а
  `PrecipitationDaysCalculation` вычисляет местные даты осадков.
- `MetricStatistics`, `DistrictStatistics`, `TemperaturePoint` — неизменяемые результаты.
- `WeatherJournal` — регистрация объектов и запросы.
- `ObservationParser` — разбор массива строк и загрузка в переданный журнал.
- `ObservationParseException` — проверяемое исключение с номером строки и причиной.

## Правила модели

ID непустые, чувствительны к регистру. ID станции уникален во всём журнале.
`District` и `Station` переопределяют **оба** метода `equals/hashCode` по ID. Журнал 
запрещает повторные ID. Станции можно передать новый объект района с уже зарегистрированными 
ID и поясом: журнал сохранит переданную станцию с этим объектом района. 
Если при том же ID пояс отличается, регистрация станции завершится ошибкой — иначе местное
время стало бы неоднозначным.

Состояние не утекает: поля закрыты, модель неизменяема, коллекции результатов —
неизменяемые снимки. Изменение журнала не изменяет ранее полученные коллекции.
Журнал не предназначен для одновременной записи из нескольких потоков.

Числа должны быть конечными; давление строго положительно, скорость неотрицательна.
Повторное наблюдение одной станции в тот же `Instant` запрещено, даже если записано с другим смещением.

## Формат загрузки

Ровно 7 полей, разделённых `;`, без заголовка:

```text
stationId;ISO_OFFSET_DATE_TIME;temperatureC;pressureHpa;windSpeed;azimuth;PHENOMENON
s1;2026-09-29T09:00:00+03:00;15;1010;4;90;RAIN
s4;2026-09-29T11:00:00+05:00;9;1010;4;100;SUNNY
```

Обе строки относятся к `2026-09-29T06:00:00Z`. Допускается `Z` вместо смещения;
время без смещения не принимается. Смещение в строке определяет момент, а пояс района
станции используется для районных отчётов и показа местного времени.

Десятичный разделитель — точка. Названия enum — регистрозависимые. Пробелы по краям
полей удаляются. Пустые строки и null-элементы массива являются ошибками. Пустой массив
разрешён; null вместо самого массива — ошибка вызова (`NullPointerException`).

Парсер создаётся с журналом: `var parser = new ObservationParser(journal);`.
При неверной строке, неизвестной станции или дубликате выбрасывается
`ObservationParseException` с номером **от 1** и исходной причиной. До проверки всего
массива журнал не изменяется. Исключение проверяемое, потому что ошибка входных данных
ожидаема и вызывающий код может сообщить её пользователю и повторить загрузку.
