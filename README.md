# Метеонаблюдения по районам — вариант 14

Библиотека классов и консольная демонстрация на Java 21, Maven и JUnit 5.
Данные хранятся только в памяти и наполняются кодом; файлового ввода и БД нет.

## Сборка и запуск

Нужны JDK 21 или новее и Maven 3.9.x, доступные в PATH.

```shell
mvn clean verify
java -jar target/task1-1.0-SNAPSHOT.jar
```

Только тесты: `mvn test`. Документация: `mvn javadoc:javadoc`
(результат — `target/reports/apidocs/index.html` для настроенной версии плагина).
Артефакт содержит библиотеку и точку входа `com.mrdoodeth.Main`; отдельные Maven-модули
для этой небольшой работы не нужны. JUnit используется только в тестах.

## Модель и структура

- `meteo.model.District` — record с ID и часовым поясом календарных отчётов.
- `Station` — неизменяемый record с ID и ссылкой на район. Часовой пояс станции
  определяется через `station.district().zone()`.
- `Observation` — record: ID станции, `Instant`, температура °C, давление гПа,
  скорость м/с, направление ветра и одно явление погоды.
- `WindDirection` — восемь секторов по 45°, азимут от севера по часовой стрелке.
  Нижняя граница включена, верхняя исключена; север — [337.5°, 360°) и [0°, 22.5°).
  Ввод 360°, отрицательных чисел, NaN и бесконечности отклоняется.
- `WeatherPhenomenon` — NONE, SUNNY, CLOUDY, RAIN, SNOW, HAIL, FOG, THUNDERSTORM.
- `ObservationCalculation<R>` — типизированный интерфейс с полиморфным `calculate`.
  `WeatherMetric` считает min/max/average по выбранному показателю,
  `DailyTemperatureCalculation` строит суточный ряд, а
  `PrecipitationDaysCalculation` вычисляет местные даты осадков. Журнал вызывает
  их через общий интерфейс; расчёт температуры также используется при поиске
  дней с отклонением от нормы.
- `MetricStatistics`, `DistrictStatistics`, `TemperaturePoint` — неизменяемые результаты.
- `meteo.WeatherJournal` — регистрация объектов и запросы.
- `meteo.ObservationParser` — разбор массива строк и атомарная загрузка в переданный журнал.
- `ObservationParseException` — проверяемое исключение с номером строки и причиной.

## Правила модели

ID непустые, чувствительны к регистру. ID станции уникален во всём журнале.
`District` и `Station` переопределяют **оба** метода `equals/hashCode` по ID;
это идентичность сущностей, а не стандартное равенство record по всем полям.
Два района с одинаковым ID равны даже при разных поясах. Журнал запрещает повторные ID.
Станции можно передать новый объект района с уже зарегистрированными ID и поясом:
журнал сохранит станцию со своим экземпляром района. Если при том же ID пояс отличается,
регистрация станции завершится ошибкой — иначе местное время стало бы неоднозначным.

Состояние не утекает: поля закрыты, модель неизменяема, коллекции результатов —
неизменяемые снимки. Изменение журнала не изменяет ранее полученные коллекции.
Журнал не предназначен для одновременной записи из нескольких потоков.

Числа должны быть конечными; давление строго положительно, скорость неотрицательна.
Климатические пределы температуры намеренно не задаются. `BigDecimal` из JDK применяется
в суммировании, чтобы среднее конечных значений не переполнялось; результат остаётся `double`.
Повторное наблюдение одной станции в тот же `Instant` запрещено, даже если записано с другим смещением.

## Операции

| Метод | Семантика |
|---|---|
| `addDistrict`, `addStation`, `addObservation` | Проверяют связи, ID и дубликаты |
| `statistics(id, from, to)` | min/max/average/count для трёх показателей в [from, to) |
| `dailyTemperature(id, day)` | Все станционные точки за день района, сортировка по времени и ID |
| `precipitationDays(id, from, to)` | Уникальные отсортированные даты дождя, снега и града |
| `observationsAt(id, instant)` | Наблюдения района в один момент, независимо от местного времени |
| `abnormalDays(id, fromDay, toDay, norm, threshold)` | Дни с абсолютным отклонением средней температуры строго больше порога |
| `new ObservationParser(journal).parse(lines)` | Атомарная загрузка массива строк в журнал |

Среднее считается по всем наблюдениям с одинаковым весом каждой записи: станции
с более частыми измерениями влияют сильнее. Суточный ход не усредняет разные станции
и не интерполирует пропущенные часы. Календарные дни всех отчётов определяются поясом
**района**; границы строятся через `atStartOfDay`, включая дни перехода DST.

В повышенном уровне норма — переданная среднесуточная температура в °C, а не автоматически
вычисленная климатическая норма. Диапазон дат [fromDay, toDay) включает полные местные дни.
Порог конечный и неотрицательный: равенство порогу не считается отклонением.
Дни без измерений пропускаются. Гроза не гарантирует осадки; при одном значении enum
сочетание грозы и дождя отдельно не кодируется.

Пустая выборка статистики — `Optional.empty()`, остальных запросов — пустой список.
Неизвестные ID и обратные/нулевые периоды отклоняются, а не трактуются как отсутствие данных.

## Формат загрузки

Ровно 7 полей, разделённых `;`, без заголовка:

```text
stationId;ISO_OFFSET_DATE_TIME;temperatureC;pressureHpa;windSpeed;azimuth;PHENOMENON
s1;2026-09-29T09:00:00+03:00;15;1010;4;90;RAIN
s4;2026-09-29T11:00:00+05:00;9;1010;4;100;SUNNY
```

Обе строки относятся к `2026-09-29T06:00:00Z`. Допускается `Z` вместо смещения;
время без смещения не принимается. Смещение в строке определяет момент, а пояс района
станции используется для районных отчётов и показа местного времени.
Станции разных районов могут иметь разные пояса. Поэтому ввод не зависит от неоднозначности
локальных часов при осеннем переходе DST.

Десятичный разделитель — точка. Названия enum — регистрозависимые. Пробелы по краям
полей удаляются. Пустые строки и null-элементы массива являются ошибками. Пустой массив
разрешён; null вместо самого массива — ошибка вызова (`NullPointerException`).

Парсер создаётся с журналом: `var parser = new ObservationParser(journal);`.
При неверной строке, неизвестной станции или дубликате выбрасывается
`ObservationParseException` с номером **от 1** и исходной причиной. До проверки всего
массива журнал не изменяется. Исключение проверяемое, потому что ошибка входных данных
ожидаема и вызывающий код может сообщить её пользователю и повторить загрузку.

## Демонстрация и тесты

`Main` создаёт 5 районов в разных поясах, по 3 станции в каждом и загружает
180 наблюдений (по 3 измерения в день в течение 4 дней на каждую станцию).
Показывает статистику каждого района,
суточный ход, дни с осадками, один момент в разных поясах, отклонения от нормы,
а также сообщение об ошибке второй строки и отсутствие частичной загрузки.

JUnit-сценарии находятся в `src/test/java`: границы румбов, некорректные числа,
контракт equals/hashCode и коллекции, полиморфизм, валидация результатов, статистика,
границы периода, чужие районы, пустые выборки, неизменяемость, DST, общий Instant,
осадки, формат и номер строки, дубликаты, атомарность, строгий порог нормы и переполнение.
Сценариев больше требуемых двенадцати. Наличие исходников тестов не означает, что они
были запущены: перед сдачей необходимо выполнить команды сборки выше.
